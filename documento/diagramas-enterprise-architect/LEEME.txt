OPCIÓN A: IMPORTAR EL XMI (recomendada)
---------------------------------------
1. Abra Enterprise Architect y cree un proyecto nuevo
   (Start > New Project / "Nuevo proyecto"), por ejemplo carrera_administracion.qea.
2. En el Explorador del proyecto (Project Browser) seleccione el nodo raíz del
   modelo o cree una vista/paquete vacío (clic derecho > Add View / Add Package)
   y déjelo seleccionado.
3. Menú Publish (Publicar) > grupo "Model Exchange" > Import > "Import XMI..."
   (atajo Ctrl+Alt+I). En versiones antiguas: Project > Import/Export >
   "Import Package from XMI".
4. En "Filename" elija modelo_carrera_administracion.xmi.
   Deje marcada la opción "Import Diagrams" y DESMARCADA "Strip GUIDs".
5. Pulse "Import" y espere a que termine (puede tardar uno o dos minutos).
6. Abra cada diagrama desde el Explorador del proyecto (doble clic).


OPCIÓN B: EJECUTAR EL SCRIPT (si algún diagrama no se dibuja bien con el XMI)
-----------------------------------------------------------------------------
Úsela en un proyecto NUEVO (no en el mismo donde importó el XMI, para no duplicar).
1. Cree un proyecto nuevo y en el Explorador del proyecto cree un paquete vacío
   (por ejemplo "Modelo") y déjelo SELECCIONADO.
2. Abra la ventana de Scripting: menú Specialize (Especializar) > Tools > Scripting
   (en versiones antiguas: Tools > Scripting).
3. Cree un grupo de scripts de tipo "Normal" y dentro un script nuevo de tipo
   JScript (botón "New JScript").
4. Abra crear_modelo_EA.js con el Bloc de notas, copie TODO el contenido,
   péguelo en el editor del script y guarde (Ctrl+S).
5. Vuelva a seleccionar el paquete vacío en el Explorador y ejecute el script
   (botón "Run Script"). Al terminar aparece el mensaje "Modelo creado".
   El avance se ve en la ventana "System Output > Script".


EXPORTAR CADA DIAGRAMA A PNG
----------------------------
1. Abra el diagrama.
2. Clic derecho en una zona vacía del diagrama > "Save as Image..."
   (o la opción "Copy Image to Clipboard" para pegarla directo en Word).
3. Elija formato PNG y guarde con el número del diagrama (ej. 02_CU1.png).
4. Insértela en el documento en la figura indicada en la lista de abajo.

Si quiere exportar todos de una vez: clic derecho sobre el paquete raíz >
"Documentation" / "Publish" > "Save Diagrams as Images" (el nombre exacto cambia
según la versión de EA).


AJUSTES RÁPIDOS SI ALGO NO SE VE IGUAL AL EJEMPLO
-------------------------------------------------
- Boundary / Control / Entity se ven como rectángulos: seleccione los elementos,
  clic derecho > Appearance (o Advanced) > desmarque "Use Rectangle Notation".
- En "Vista de Paquete ..." el paquete tapa a los actores: clic derecho sobre el
  paquete > Z-Order > "Send to Back".
- Mensajes de secuencia muy juntos o encimados: arrástrelos verticalmente o use
  Layout > "Auto-Layout" del diagrama de secuencia.
- Líneas cruzadas en diagramas de clases: Layout > Diagram > "Layout Diagram"
  (o mueva las cajas a gusto). Todas las relaciones ya están creadas.
- Si no desea la leyenda "(from ...)": Diagram > Properties > Elements >
  desmarque "Show Namespace" / "Show element's package".

DECISIONES DE MODELADO (coinciden con la documentación)
-------------------------------------------------------
- Actores: Administrador, Encargado de Módulo (Responsable de Noticias, Encargado
  Revista INNOVAR, Administrador de Graduados, Secretaría Académica), Graduado y
  Visitante. El "Propietario, Vendedor, Cliente" del enunciado del docente se
  interpreta como Administrador, Encargado de Módulo y Graduado/Visitante.
- Paquetes: Seguridad y Portal (CU1, CU2); Gestión Académica e Investigación
  (CU3, CU4); Vinculación y Difusión (CU5, CU6); Atención y Análisis (CU7, CU8).
- «include»: CU3, CU4, CU5 y CU6 incluyen CU2 (todo cambio queda en la bitácora);
  CU7 incluye CU3, CU4 y CU6 (la búsqueda global recorre su contenido);
  CU8 incluye CU2 (usa el contador de visitas y la bitácora).
- Análisis: boundary = páginas Vue, control = controladores Laravel,
  entity = modelos Eloquent. Diagramas de clases generados desde el código real
  (app/Http/Controllers, app/Models, app/Http/Middleware, resources/js/pages).
